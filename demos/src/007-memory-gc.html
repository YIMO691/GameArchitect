      What this shows
      
    
      
      
      Two separate knobs
      Garbage per frame decides how often the GC runs. Live data decides how long it runs. Free room only moves the hitch later.
      
      
      The payer is not the culprit
      GC.Collect shows up inside whichever call allocated when the room was full. Read the GC Alloc column to find who filled it.
      
      
      Hide vs remove
      Incremental GC spreads the same work over several frames. Pools and arenas remove the garbage, so there is nothing to collect.
      
    
      
    
      This lab is a model, not a measurement. Numbers come from Lesson 007: CPU 13.5 ms and GPU 14.5 ms per frame, 1.5 KB of garbage per splash, 4 KB per frame from HUD strings, GC work of 0.3 ms per MB of live data, 3 ms incremental slices. A real collector (Unity's Boehm GC, .NET, Unreal's UObject GC) has more rules: heap growth, write barriers, and a fall-back to a full stop when garbage outruns the slices. The workbenches below (Lesson 040 on) use the same GC rule with each lesson's own numbers.
