        What this shows
        
    
        
      
        Components fix design, not speed
        The Gull became a prefab with no new class, but 11,000 engine calls and hops to the Transform made the step slower: 2.75 ms.
        
      
        ECS: columns and systems
        Each system reads a few packed arrays from start to end. No jumps, no per-critter call, nothing unused loaded: 10 ns per visit. 1,600 Splashing tag changes cost 0.80 ms; a bool field costs almost nothing.
        
      
        Tables vs sparse sets
        Archetype tables are fast to read (10 ns per visit) but slow to change: each add or remove moves the entity, 0.5 µs. Sparse sets change in 20 ns but join with lookups: 45 ns per visit. A hybrid keeps movement in tables and statuses in sparse sets: 0.21 ms in the storm.
        
    
        
    
        This lab is a simulation, not a measurement. Costs per update come from Lessons 012 and 013's phone numbers (approximate): fat base class 190 ns, component update 250 ns, ECS visit 10 ns (tables), 45 ns (sparse sets) or 15 ns (hybrid, with a Stunned check), table move 0.5 µs, sparse-set add or remove 20 ns. The mix is always 40% fish, 30% birds, 20% crabs, 10% gulls. The memory view is a sketch: it is slowed down a lot, and array lengths are not to scale. Real engines differ in the details, not in the shape.
