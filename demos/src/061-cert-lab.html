Lesson 061: certification

    What this shows

    A local fix finds the next failure

    Fixing only the screen the tester reported leaves the same problem on every other screen. The next submission finds it there, two weeks later.

    Rules become systems

    Controller loss, suspend, sign-out, saving and button names are handled once, in a layer every screen uses. Whole groups of checks stop failing.

    Find it before they do

    Running the platform's checklist yourself, partly automated in CI, turns a 2-week round into a 5-day one, and the real submission passes first time.

    This lab is a model, not a real certification. It uses Lesson 061's numbers: 8 groups of checks; when only reported screens are fixed, the same group fails again in other places the next round (for example controller loss: 3, then 2, then 1). A submission round takes 14 days from sending the build to getting the result and a fixed build ready; an in-house pre-certification round takes 5 days. Real platforms, rules and turnaround times differ, and their actual requirements are confidential.
