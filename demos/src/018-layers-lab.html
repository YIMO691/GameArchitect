Lesson 018: layers and dependency rules

      
    
    
    
  
    

  
    
    
    What this shows
    
    
    
      
    A tangle builds as one
    Unity can't split modules that depend on each other in a circle. Three upward arrows, led by Core → UI, tied 8 modules together, so 10 assemblies still waited 48 s for a HUD edit.
    
      
    Down arrows, short waits
    An edit rebuilds its module and everything above it. With no upward arrows a HUD edit is 12 s. Core is at the bottom, so a Core edit is always 48 s: keep it small.
    
      
    Layers plus an allow-list
    Simulation → Audio and Simulation → Render point down, but they stop the simulation running headless. Only a machine check catches the next one on the day it is written.
    
    
    
    
    This lab is a simulation, not a measurement. Compile times are the lesson's approximate editor-log numbers (Core 3, Platform 3, Physics 4, Render 7, Audio 2, Simulation 9, HUD 5, UI 5, Tools 3, Boot 1 s) plus a fixed 6 s reload. The day's edits are 30% HUD, 30% Simulation, 15% UI, 10% Tools, 5% Render, 5% Core, 3% Physics and 2% Audio. The lab adds the times up; real Unity compiles some assemblies in parallel and its reload grows with the amount of code, so real waits differ a little.
